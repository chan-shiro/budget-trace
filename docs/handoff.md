## 1. これは何か

**予算トレース** — 地方自治体の予算（歳入・歳出）から補正・執行率・支出先・事業報告までを
一次資料（エビデンス）付きでたどれる可視化サイト。
**決算は全1,741市町村**（総務省）、**当初予算（款別）は 124団体＋full の甲府市**（**都道府県44＝収録可能な全県**＋
全20政令指定都市＋**東京特別区23区**＋**中核市など25市（2026-08-22〜・人口順）**＋山梨県内＋類似市。**新宿が H13〜R8 の26年度で最長**、次いで**文京が22年度**）、
**甲府市だけが予算→事業→成果→議会まで通っている**（他の自治体もこの深さを目指す）。
⚠ **件数の正は `public/coverage.json`**（derive の出力）。この行を含め docs の数字は追記時点のもの。

Claude Design のプロトタイプ（`project/予算トレース.dc.html`）を Next.js で本実装したもの。
`project/` は元デザインの**参照用アーカイブ**（編集・import しない）。会話ログ `chats/` は 2026-07-18 に追跡から外した（git 履歴にはある）。

### ✅ 項・目に前年比が付いた（2026-08-03・#192・§8d-3）

#191 の**過年度への延伸**。横浜の CSV 形式は R6〜R8 の3年しか無く、**R5 以前は同内容が
`rNippan.zip` 内の XLSX**。そちらは **CSV に無い「前年度」列**を持つので、
**項・目レベルの前年比**が出せる（R5・R4・R3 を収録。パーサ `yokohama-setsumeisho-xlsx`）。
前年度列を持たない R8・R6 では**列ごと出ない**（無いことを 0% と書かない）。

**一般則として残るもの**:

1. **⚠⚠⚠ 合計を「下位の和」で作り直さない — 原典が上の階層にも印字しているならそちらが正。**
   この様式は**当年度の構造**を並べるので、**当年度に廃止された目は行ごと消える**が、
   その前年度額は**項行・款行のセルには残っている**。項の前年度を Σ目 で作ったせいで、
   **画面の前年比が符号ごと逆になった**（R5 歳出「選挙費」は実際は −20.5% なのに **+50.1%**。
   3年で13項）。**レビューが見つけた** — Σ が立っていたので検証ゲートは全部緑だった。
   → **上位の行に値があるなら、下位の和で代用しない**。
2. **⚠⚠⚠ 総和のゲートは局所の間違いを隠す。そして「1段上」とだけ比べる。**
   当時の網は「**Σ葉の前年 ≦ 前年合計**」＝**全体の和**しか見ていなかったので、
   「ある項では足りない」「別の項では多い」が**相殺して素通り**した。
   → **項ごと・款ごとに**張り直した。**Σ を張ったことと、Σ が意味のある粒度で張られていることは別**。
   ⚠ **張り直しの1回目も間違えた** — 款を「**Σ目** ≦ 款行」で張ってしまい、
   **項行だけが一様に過大**な壊れ方（実害を出した壊れ方のちょうど鏡像）が素通りする穴が残った。
   **レビューの2巡目が見つけた**。**中間の階層を飛ばして張ると、その階層の値には証人がいない**。
3. **⚠⚠ 「その資料の価値そのもの」の列には、単独の資料では張れない網を別の層で張る。**
   前年度列こそがこの資料を CSV 版より優先する理由なのに、**validate は1資料の中しか見ない**。
   → derive の出口に**2本**張った: ①**同じ年度の款別一覧の前年度当初額と突合**（129款すべて一致）

### ⚠ raw のファイル名は basename だけでは足りない（2026-08-04）

**`pipeline:fetch` は URL の basename で raw を保存していたので、別ディレクトリの同名ファイルが
静かに上書きされていた。** 横浜の事業計画書（#164）は医療局と議会局がどちらも
`0001_20260126.pdf` で、**62本を登録したのに raw には61本しか残らなかった**。

**気づけない理由が2つ重なっている**:

1. **上書きはエラーにならない** — 「旧/新 の sha256 が違う」というログを出して**成功として続行**する
2. **derive の魚拓チェックはソース単位の `some`** なので、複数ファイルのソースで1本欠けても鳴らない
   （#163 で別途踏んだ型と同じ）

→ **既に別の URL から同名で登録されていたら、相手の URL と実際に食い違うセグメントを前置する**
（`gikai__0001_20260126.pdf`）。⚠ **「一意になる最短の名前」を採らない** — 直上のディレクトリは
相手と同じことが多く（横浜はどちらも `r8jigyoukeikaku.files`）、一意でも**人が読めない名前**になる。
**この名前は画面の出典ラベルに出る**。

**一般則**: **取得の成否は件数で確かめる**。「✓ が並んだ」は取得できた証拠にならない。
既存486ソースは衝突ゼロなので、この変更は**実際に衝突したときだけ効く**（実測で確認済み）。

### 2-2. 版面の型が出揃った（これが政令市収録の本体）

**「実測してから着手する」以外に方法が無い。**スカウトの構造報告は**毎回外れうる**
（神戸「無改修で乗る」→ 乗らない／静岡「中央寄せ3行型」→ 実際は別型／相模原「面付けで重複」→ 実態が違う）。

> **2026-07-16 追記（特別区で再発 → 手を打った）**: 千代田「見出し指定は不要」→ 実際はパーサが
> 見出しの存在を必須チェックしていて throw、など**同じ型の誤報が特別区でも3種類出た**。
> 原因は**スカウトが registry を書けずパイプラインを走らせられないため、「乗るか」を推論でしか
> 答えられなかった**こと。→ **`bun run pipeline:try-parse <parser> <file> --opts '<JSON>'`** を新設した
> （registry も data/ も触らないドライラン。抽出できた款の全件＋Σ照合を出す）。
> スカウトはこれを当てて実測で報告するようになったが、**それでも鵜呑みにしない** —
> 今回は**5体が揃って「licenseClassOf の語彙が当たらない」と誤報**し、実際に足りないのは2件だけだった
> （docs の要約を正規表現と取り違えていた）。**収録時は自分でコードとデータに当たること。**

  → **`D.seriesColor(i)` に集約し、周ごとに明度を振る**（2周目＝白へ55%・3周目＝黒へ40%）。
  **色相は新設していない**ので CLAUDE.md の「PALETTE 以外の系列色を新設しない」は不変。
  ⚠ **`PALETTE[i % length]` を直接書かないこと** — 11か所あった呼び出しを全部 `seriesColor` に
  置き換えた。新しいチャートもこれを通す。`color-mix` は入れ子で使える（`fadeColor` の退色と
  組み合わせて conic-gradient 内で解決することを実測済み）
  - **2周目をはっきり淡くしてある**のは、1周目の彩度の高い色と「層」として見分けさせるため。
    中途半端に淡くすると**別の色相の1周目と紛れる**（淡くした青 と 空色）

### 2-8. 「調べたが収録できない」を /coverage の外へ配った（2026-07-29）

**`/coverage` だけが知っていても足りなかった。** 読者が実際に歩くのは**市区町村選択と
ダッシュボード**で、そこでは「調べたうえで収録できない」団体が**未着手の団体とまったく
同じ顔**をしていた（山形県＝「準備中」・山梨市＝「決算ベース（総務省）」）。さらに
**取れないと分かっているものへリクエストを起票させていた** — `/coverage` が
「調べたが収録できない列はリクエスト先から外す」と決めたのと**正反対のことを、同じデータに
ついて**やっていた。

- **配り方**: `coverage.json` は **882KB**（docs が言う「130KB」から育っている）で
  `/coverage` と `/sources` でしか取らない方針なので、**判定だけを抜いた 14KB の
  `src/client/lib/unrecordable.gen.ts`** を derive に焼かせて静的 import する。
  ⚠ **収録できたら derive が throw する**既存の仕組みはそのまま効くので記録は腐らない
- **`UNRECORDABLE_WHOLLY` と `UNRECORDABLE_BY_CODE` を分けてある**。画面の文言を差し替える
  対象は**1年度も収録できていないもの（13団体）だけ** — 収録済みで一部年度のみ不可
  （`/coverage` の ○*・千代田区や堺市など15件）は**「収録済み」の案内のままで正しい**。
  ここを混ぜると「収録済みなのに収録不可と書いてある」事故になる
- **直した3か所**: 市区町村選択のカード（`決算のみ（予算は収録不可）`）／県全体ボタン
  （`準備中` → `収録不可`。**「準備中」はこれから手を付ける約束に読める**）／
  decision ダッシュボードのリクエストチップ（→ 理由と確認日のパネルに差し替え）
- ⚠ **「できない」を恒久の事実として書かない**という registry の規約を画面側にも通した。
  文面は必ず**確認日つきの実測**として出し、「恒久的にできないという意味ではありません」を添える

⚠ **derive は gen を全件焼き直すが、この変更では既存 gen が1バイトも変わらなかった**
（新規ファイルの追加のみ）。並行して収録セッションが走っているときは、**マージ直前に
derive し直して差分が新規ファイルだけであることを確認する**こと。

### 2-9. /roadmap の「年度の深さ」に手書きの行が残っていた（2026-07-29）

**`/roadmap` は「進捗の数字を手書きしない」ページなのに、`BudgetTraceView.tsx` の JSX に
甲府市の行がべた書きされていた**（`v.rm.depth` を回したあとに1行追加していた）。実害は2つ:

- **ソートの外に置かれるので、7年度なのに2年度の自治体より後ろに出ていた**（末尾が
  `…さいたま市 2年度 / 千葉市 2年度 / 新潟市 2年度 / 三重県 2年度 / 甲府市 7年度`）
- **団体名「甲府市」が手書き**＝ derive の実データから切れていた

→ **`budgetDepth` に甲府（full）を含めて derive 側で並べる**。甲府は full 階層なので
`MUNI_BUDGET_YEARS` でなく `KOFU_BUDGET_YEARS` を持つ、というだけの理由で外に出ていた。
あわせて**同年度数の並びを団体コード順で解く**ようにした（件数だけで並べると、年度を
足すたびに同数グループの中の順序が不定に入れ替わって差分がノイズになる）。

⚠ **derive が数字を出しているページでも、JSX 側で1行足せば手書きは戻る。**
`/roadmap` の3ルール（Markdown・時期の約束・進捗の数字）は **registry の文言しか検査して
いない**ので、**画面の JSX に書いた行は素通りする**。この型は §2-3 で「手書きの数字が残って
いた」として一度潰しているが、**潰したのは registry 側だけだった**。

### 2-10. /sources を直接開いたときに甲府市の文脈が付いていた（2026-07-29）

`/sources` は**全473資料を横断する全体ページ**なのに、直接開く（＝共有リンクやトップの
フッターから来る）と**アプリヘッダーが甲府市の文脈**で出ていた — パンくず
`日本 › 山梨県 › 甲府市`・R8 の年度セレクタ・甲府のタブ・「← ダッシュボードへ戻る」。
同じ全体ページの `/coverage`・`/roadmap` は素の「← トップへ戻る」だけなので、そこだけ不揃いだった。

**区別はもとから URL に入っていた** — `routing.ts` の `stateToPath` は
`screen === "sources" && !muni` を `/sources`、自治体スコープを `/yamanashi/kofu/sources` に
振り分けている。**URL は正しく、ヘッダーの出し分けが無かっただけ**。

- `isGlobalSources = isSources && !s.muni` で**ヘッダーごと出さない**（パンくず・年度
  セレクタ・タブ・単位切替はどれも「いま見ている自治体」のもので、横断ページに載ると
  誤った文脈になる）
- 戻り先も来た経路に合わせる。**行ったことのない甲府市へ「戻る」と書かない**

⚠ **自治体スコープの `/yamanashi/kofu/sources` は従来どおり**（ダッシュボード末尾の出典
リンクから来る経路）。ユーザー判断は「直接来たときはトップに戻るだけでよい」（2026-07-29）。

### 2-11. 独自ドメインへ移行し、公開用の設定を入れた（2026-07-30）

**`https://budget-trace.phh.jp`** へ移行した（`budget-trace-tawny.vercel.app` も生きているが
**canonical はこちらへ向けている**ので、検索エンジンには1本化して見える）。
**ドメインは `src/client/lib/site.ts` の1か所**に持たせた — OGP・canonical・robots・sitemap が
すべてこれを基準にするので、別々に直書きすると必ずどれかが古いまま残る（このリポジトリが
繰り返し踏んでいる手書きの二重管理と同じ型）。

**入れたもの**:

| | 中身 |
| --- | --- |
| OGP / Twitter Card | `layout.tsx` が既定、`generateMetadata` が画面ごとの `title`・`canonical`・`og:url` を上書き |
| OG 画像 | `public/og.png`（1200×630・54KB）。**数字を焼き込んでいない** |
| canonical | `stateToPath` で正規化してから入れる。旧・日本語パスで来ても正典は1本 |
| robots | 全体は許可。**`/sources/` `/decision/` `/reports/` `/mapdata/` `/vendor/` `coverage.json` を除外** |
| sitemap | **1,831 URL**（全体4＋都道府県47＋収録済み95＋決算のみ1,685） |
| GTM | `GTM-MQRPKN33`（コンテナは `*.phh.jp` 対象）。`layout.tsx` に直書き＝依存を増やさない |

⚠ **踏んだ罠**: **Next は `openGraph` / `twitter` をフィールド単位でなくオブジェクトごと
子で置き換える**。`generateMetadata` 側で `openGraph` を指定した瞬間、layout に書いた
`images` が丸ごと落ちて **`og:image` が消えた**（curl で実測して気づいた）。
→ **画像は layout とページの両方で明示する**（`OG_IMAGE` を共有して書く）。

⚠ **GTM は `process.env.VERCEL_ENV === "production"` でだけ読む**。Preview デプロイ
（`*.vercel.app`）や dev で読むと、**公開前の試行がそのまま計測に混ざる**。ローカルでは
`VERCEL_ENV` が undefined なので自動的に無効（実測: ローカルの HTML に `GTM-` は0件）。

⚠ **`robots.ts` が `/sources/` を除外している理由**は crawl budget ではない。あそこは
**エビデンスの原本コピー**（発行元の PDF・HTML・Excel）を配信しているディレクトリで、
**発行元の資料が発行元より上位に検索結果へ出かねない**。エビデンス3層の③は「消えたときの

1. `src/app/og-gen/route.tsx` を作る（`next/og` の `ImageResponse`。Google Fonts の

   commit するのは PNG だけ
4. 改行はサイトの h1 と同じ位置で**明示的に割る**（自動折返しに任せると「執行ま／で。」と
   語中で割れる。実際に1回焼き直した）

**未対応（判断が要る）**: **プライバシーポリシーのページが無い**。GTM を入れた以上、
市民向けの公開サイトとしては「何を計測しているか」を書いた1ページがあったほうがよい。

### 2-12. Cookie 同意を www.phh.jp と揃えた（2026-07-30）

`www.phh.jp` は同意を必須にしている（`/privacy` に「分析目的の Cookie は同意バナーで
同意をいただいた場合にのみ有効」と明記）。**同じ GTM コンテナ `GTM-MQRPKN33` を使う
budget-trace が未同意で計測すると、公開しているポリシーと食い違う**ので揃えた。

**www.phh.jp の実装を実測して合わせた**（バナーは操作せず、配信中の JS チャンクを読んだ）:

| | 中身 |
| --- | --- |
| ライブラリ | `vanilla-cookieconsent` 3.1.0（MIT・**依存ゼロ**） |
| 同意 Cookie | `cc_cookie` / **`domain: ".phh.jp"`** / 182日 / Secure / SameSite=Lax |
| カテゴリ | `necessary`（readOnly）+ `analytics` の2つ |
| 既定値 | Consent Mode v2 で `ad_*`・`analytics_storage` を **denied**、`functionality`・`security` を granted、`wait_for_update: 500` |
| 文言 | 「Cookie の使用について」「すべて同意」「必須のみ」「設定を管理」 |

⚠ **`cc_cookie` を `.phh.jp`（親ドメイン）に置くのが要点**。www.phh.jp が同じ設定で
書いているので、**どちらかで同意すればもう一方では二度目を訊かれない**。
**名前・ドメイン・カテゴリ名のどれかがズレると共有が黙って壊れ**、利用者はサブドメイン
ごとに同じ質問をされる。ここがこの実装で一番壊れやすい。

⚠ **Consent Mode の既定値は GTM より前に入れる**（`beforeInteractive`）。後から入れると
GTM は「既定＝granted」として**一度発火してしまう**。HTML 内の出現位置で検証した
（既定 3,315B < `gtm.start` 43,417B）。

⚠ **GTM は「読むか読まないか」でなく「読んだうえで同意状態を渡す」**。読み込み自体を
止めると、同意した瞬間に計測を始められず再読込が要る。

**プライバシーポリシーは `www.phh.jp/privacy` を正典にした**（2026-07-30 のユーザー判断）。
事業者も計測の仕組みも同一で、2つに分けると必ず片方が古くなる。⚠ **`PRIVACY_URL` は
絶対 URL** — www.phh.jp のバナーは相対 `/privacy` を書いているが、こちらで相対にすると
存在しないページを指す。フッター（トップ・アプリ共通の2か所）から「プライバシーポリシー ↗」と
「Cookie 設定」（同意の再設定）へ出せるようにした。

**実測で確認したこと**（`VERCEL_ENV=production` でビルドして `next start`）:
同意前は Cookie が0件 / 「必須のみ」で `cc_cookie` が `["necessary"]`・update が denied /
「すべて同意」で `["necessary","analytics"]`・update が granted / 選択後はバナーが再表示されない /
フッターの「Cookie 設定」で設定モーダルが開く。

⚠ **GA4 が実際に `_ga` を書くところまではローカルで確認できていない**（コンテナ側の
タグ条件と検証用ブラウザの事情が混ざるため）。**本番ドメインで一度確認すること。**

## 4. 横断的な暗黙知（ハマりどころ）

- **依存は Next 16 + React 19（2026-07-14 更新）／`bun audit` 0 件を維持する**。更新前は Next 14 系で
  **17件（high 7）** の既知脆弱性があった（Server Components の DoS・WebSocket SSRF 等。next ≥15.5.16 で修正）。
  Next はおおむね直近2メジャーしか修正が出ないので、**メジャー遅れを放置しない**。ハマりどころ:
  - **xlsx は `pipeline/lib/xlsx.ts` 経由でのみ使う**（`"xlsx"` を直接 import しない）。SheetJS は 0.18.5 で
    npm 公開を停止 → 公式 CDN 版を devDependency で導入（`https://cdn.sheetjs.com/xlsx-0.20.3/...tgz`）。
    ESM ビルドは `readFile` が fs を掴まず "Cannot access file …" で落ちるため、ラッパで `set_fs` 済み。
    **アプリ本体は xlsx を使わない（パイプライン専用）**ので devDependencies が正しい
  - `postcss` は Next が 8.4.31 固定 → `overrides` で 8.x 最新へ（GHSA-qx2v-qp2m-jg93）
  - React 19: グローバル `JSX` 名前空間が廃止 → `React.JSX`。`Record<string, unknown>` と交差した props は
    既知プロパティが `unknown`/`{}` に落ちるので使う分だけ絞り込む（`ui.tsx` の HoverBox）
  - Next 15+: `params`/`searchParams` は Promise → catch-all ルートで `await`
  - TypeScript は 5.5 のまま（7 系は Go 実装で飛躍が大きく、脆弱性指摘も無いため別途）
- **ブラウザ検証ツールの限界**: プレビュー用ヘッドレスブラウザは**コンポジットしない**ため
  (a) スクリーンショットが body 背景だけの空画像になる (b) viewport が 0×0 になることがある
  (c) **IntersectionObserver のコールバックが一切発火しない**（自明に可視な要素でも）。
  → **PdfViewer の遅延描画（IO でページを描く）はこのツールでは検証できない**（PDF.js の読込・
  ページ数・ビューポート計算・初期スクロールまでは確認可能）。DOM 検証（`get_page_text` /
  `getBoundingClientRect` / computed style）は信頼できるので、そちらで確認する
  - **(d) `requestAnimationFrame` も発火しない**（2026-07-16 に実測。rAF を待つ Promise が
    タイムアウトする）。→ **`CountUpNum` の数値はこのツールでは常に `0万円` に見える**
    （`useState(0)` から rAF でカウントアップする実装のため）。**これはバグではない** —
    ダッシュボードの「歳入合計/歳出合計」と総額だけが CountUpNum で、**款別の内訳は静的なので
    正しい値が読める**。総額を検証したいときは内訳か gen 側の値で確認すること。
    なお `prefers-reduced-motion: reduce` なら即座に確定値を出すので、実ユーザーには影響しない

- **GitHub 運用**: **`main` へ直接 push しない**（main push = 本番デプロイ。必ず作業ブランチ → PR →
  squash マージ。「マージしよう」は PR を作れの意）。このリポジトリは **squash マージが使われる**。マージ後は必ず
  `git fetch origin main && git checkout -B implement-budget-trace origin/main` でブランチを作り直す
  （古いコミットを積み直すと重複する）
- **データ来歴**: 画面の「ダミー」「推計」注記は仕様。データを触るとき整合を崩さない。
  フィクスチャ出力（`data/normalized/_fixtures/`）をアプリから import しない
- **PALETTE はモジュール変数**: `src/client/lib/data.ts` の `setPalette()` で描画前に切替。呼び出し順に注意
- **スタイルは `S("...")` の CSS 文字列**（プロトタイプと diff 可能な形を維持）。
  ホバーは `HoverBox`、モバイルは `data-mq` 属性 + `src/app/globals.css` の media query
- **JapanMap は React 管理外の直接 DOM 操作を含む**（`boxRef` 配下の SVG）。境界を崩さない
- **地図データは `public/mapdata/` に同梱**。CDN 実行時フェッチに戻さない
- **政府系サイト（総務省・e-Stat）はクラウド環境から 403**（環境の許可リスト + 先方 WAF の2層）。
  ローカルなら制限なし（fetch.ts はブラウザ相当 UA を名乗る。R6 は自動取得できた）。
  クラウドで通す場合は環境設定で `*.soumu.go.jp` 等を Custom 許可
  （「Also include default list …」に必ずチェック。外すと git/bun が壊れる）
- **決算状況調の実ファイルの構造**（R6 で確認。パーサ 0.2.0 が対応済み）:
  1年度 = 4ファイル（都市別/町村別 × 概況/目的別歳出内訳）で、団体コードでマージする。
  ヘッダは複数行（目的別は 款番号/科目名・連番/内訳名 の3段＋結合セル）。
  労働費・諸支出金は総額列がなく内訳列の合算。「（参考）一般行政経費」ブロックは
  款名を再掲するので列解決から除外。都道府県名の列はなく「団体コード空 + 団体名だけ」の
  区切り行（字間スペース入り）で県が変わる。特別区は都市別ファイルに含まれる
- **描画用値オブジェクト `v` は any のまま**（プロトタイプ移植由来・eslint-disable 付き）。
  新規コードでは倣わない。サーバー層導入時に型付けして解消する予定
- IME 変換確定 Enter のガード（CLAUDE.md 参照）— Enter ハンドラ追加時は必須
- **`pdftotext` の使い分け**（2026-07-16 に全部踏んだ）:
  - `-layout` が既定。ただし**縦書き・面付け・左右2側**があると文字が交互に混ざる（相模原 `歳歳入出`）
  - **`-layout` の表示列は当てにならない**場面がある — 款項目の文字が前に詰まると**同じ階層の行が
    別の列に見える**（相模原の主な事業は親の `○` が列27・内訳の `○` が列22 で**逆転**）。
    **階層を x で判定するなら `-tsv`（座標）を使う**。`pdfPageWords()` が既にある
  - `-x/-W` で**ページを横に切れる**（静岡）。座標を自前で組み直すより先にこれを試す
  - **`-bbox-layout` は poppler が `std::out_of_range` で落ちるファイルがある**（静岡 R5・新潟）
- **zsh は変数を単語分割しない**（このセッションで3回踏んだ）。`for t in $TARGETS` は**1回しか回らない**。
  `printf '%s\n' a b c | while read -r x` を使う
- **同じ字に見えて別の文字**が繰り返し出る: `○`(U+25CB) と **`〇`(U+3007)**（北九州の廃止款・
  相模原の事業マーカーに混在）、`−`(U+2212) と `-`。**片方だけ数えると件数が合わない**
- **`data/raw` は 475MB**。政令市を1市足すと数MB〜25MB 増える。**Wayback は MiB 境界で打ち切る**ので
  大きいファイルは②層が張れない（神戸R8 24MB→5MiB・浜松R5 3.9MB→1MiB）
